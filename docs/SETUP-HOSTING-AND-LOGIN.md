# מדריך: לשים את "כוחות" באינטרנט ולהפעיל התחברות

המדריך הזה מסביר, צעד אחרי צעד, איך:
1. לשים את האפליקציה באתר **Vercel** (חינם), כך שכל אחד יוכל לפתוח אותה מהטלפון.
2. לחבר אליה **דומיין** (כתובת) שקניתם, למשל `example.com`.
3. להפעיל את ההתחברות: **Google**, **קישור (או קוד) למייל**, ו**מייל + סיסמה** (ב-Supabase, השרת של הסנכרון).

לאורך המדריך:
- `example.com` = הדומיין שלכם. בכל מקום שכתוב `example.com`, כתבו את הדומיין האמיתי.
- `cieyeoyuwddobrxjcffw` = הפרויקט שלכם ב-Supabase (זה כבר נכון, לא צריך לשנות).
- שמות של כפתורים באתרים באנגלית כתובים באנגלית, כמו שהם מופיעים באתר. אתרים משנים לפעמים את העיצוב, אז אם כפתור נקרא קצת אחרת, חפשו משהו דומה.

> **אין סיסמאות סודיות באפליקציה.** הכתובת של Supabase והמפתח שלה (publishable key) כבר נמצאים בקוד, בקובץ `.env`. המפתח הזה נועד לדפדפן, והנתונים מוגנים בהרשאות בשרת. **לא צריך להכניס שום דבר ל-Environment Variables ב-Vercel.** אף פעם אל תכניסו לשום מקום מפתח שנקרא `service_role` או `secret`.

## א. Vercel: לשים את האפליקציה באינטרנט

### נרשמים
1. היכנסו ל-https://vercel.com ולחצו **Sign Up**.
2. בחרו את התוכנית החינמית (**Hobby**), כתבו שם, ולחצו **Continue with GitHub**.
3. GitHub ישאל אם לאשר ל-Vercel גישה. אשרו.

### מייבאים את הפרויקט
1. בלוח הבקרה של Vercel לחצו **Add New…** ← **Project**.
2. ברשימה **Import Git Repository** אמור להופיע `soccer-team`. לחצו לידו **Import**.
   - לא מופיע? לחצו **Adjust GitHub App Permissions** (או **Install**), ותנו ל-Vercel גישה למאגר `soccer-team`. חזרו לדף ורעננו.
3. בדף **Configure Project** (או **New Project**):
   - **Framework Preset**: צריך להיות **Vite** (Vercel מזהה לבד; יש גם קובץ `vercel.json` בפרויקט שאומר לו את זה).
   - **Root Directory**: להשאיר `./`.
   - **Build and Output Settings**: לא לגעת (Build Command = `npm run build`, Output Directory = `dist`).
   - **Environment Variables**: לא להוסיף כלום.
4. לחצו **Deploy**. זה לוקח בערך דקה.
5. בסוף תראו "Congratulations" ותמונה של האתר. לחצו **Continue to Dashboard**.
6. הכתובת של האתר מופיעה תחת **Domains**, משהו כמו `soccer-team-xxxx.vercel.app`. **שמרו אותה**, נצטרך אותה בהמשך.

### איזה ענף (branch) עולה לאוויר
הקוד נמצא ב-GitHub בענף `claude/loving-allen-zp89uf`. זה הענף היחיד, ולכן הוא גם ה"ראשי" (default) של המאגר, ו-Vercel משתמש בו לבד בתור **Production**. אין צורך לעשות כלום.

לבדיקה: בפרויקט ב-Vercel ← **Settings** ← **Environments** ← **Production** ← **Branch Tracking** (במסכים ישנים: **Settings** ← **Git** ← **Production Branch**). צריך להיות כתוב שם `claude/loving-allen-zp89uf`. אם כתוב משהו אחר, שנו ל-`claude/loving-allen-zp89uf` ושמרו.

**מעכשיו כל שינוי שנכנס לענף הזה ב-GitHub עולה לאתר לבד, תוך דקה-שתיים.**

> אם בעתיד תרצו ענף בשם `main`: ב-GitHub ← המאגר ← **Branches** ← **New branch**, שם `main`, מקור `claude/loving-allen-zp89uf`. אחר כך ב-**Settings** ← **Branches** של המאגר אפשר להפוך אותו ל-default, וב-Vercel לשנות את ה-Production Branch ל-`main`.
> שימו לב: בפרויקט יש גם הגדרה ישנה להעלאה ל-GitHub Pages (`.github/workflows/deploy.yml`) שרצה רק על `main`. **Vercel מחליף אותה.** אם תיצרו `main`, היא תנסה לרוץ ותיכשל (אלא אם תפעילו את GitHub Pages). אפשר להתעלם מזה, או לבקש למחוק את הקובץ.

### בודקים
פתחו את הכתובת `...vercel.app` בטלפון. האפליקציה צריכה להיפתח ולעבוד, גם בלי התחברות.

## ב. דומיין משלכם

### קונים דומיין
- אפשר לקנות בכל חברה שמוכרת דומיינים (רשם דומיינים). מחיר רגיל לדומיין `.com` הוא בערך 10–20 דולר לשנה. דומיין `.co.il` קונים אצל רשם ישראלי מורשה.
- אפשר גם לקנות ישירות ב-Vercel: בפרויקט ← **Settings** ← **Domains** ← **Add Domain** (או **Buy**). אז Vercel מגדיר הכול לבד, ואפשר לדלג על "מגדירים DNS" למטה.
- טיפ: שם קצר, בלי מקפים, שקל להגיד בקול במגרש.

### מחברים את הדומיין ל-Vercel
1. ב-Vercel: הפרויקט ← **Settings** ← **Domains** ← **Add Domain** (או **Add**).
2. כתבו את הדומיין, למשל `example.com`, ולחצו **Add** / **Save**.
3. Vercel ישאל אם להוסיף גם `www.example.com` ולהפנות אחד לשני. בחרו באפשרות המומלצת (בדרך כלל: `www` מפנה ל-`example.com`). **מה שתבחרו כאן הוא "הכתובת הראשית"; זאת שתכתבו ב-Supabase וב-Google.**
4. Vercel יראה הודעה **Invalid Configuration** ורשימה של רשומות DNS שצריך להוסיף. זה תקין, עוד לא הגדרנו.

### מגדירים DNS (אצל החברה שממנה קניתם)
1. היכנסו לאתר של החברה שממנה קניתם את הדומיין ← הדומיין ← **DNS** (נקרא לפעמים "ניהול DNS", "DNS Records" או "Zone").
2. הוסיפו **בדיוק** את מה ש-Vercel מראה. בדרך כלל:
   - רשומה מסוג **A**, שם (Name/Host) `@` (= הדומיין עצמו), ערך (Value) = כתובת ה-IP ש-Vercel מראה.
   - רשומה מסוג **CNAME**, שם `www`, ערך = מה ש-Vercel מראה (מסתיים ב-`vercel-dns.com` או משהו דומה).
   - אם כבר יש רשומה **A** ל-`@` או **CNAME** ל-`www` (למשל "דף חניה" של החברה), מחקו אותה או ערכו אותה.
   - **העתיקו את הערכים מ-Vercel, לא מהמדריך הזה.**
3. דרך אחרת: להעביר את כל ניהול ה-DNS ל-Vercel, על ידי החלפת ה-Nameservers אצל החברה לאלה ש-Vercel מראה. פשוט, אבל אז כל רשומה (גם של מייל) מנוהלת ב-Vercel.
4. שמרו.

### מחכים ובודקים
- בדרך כלל זה מתעדכן תוך כמה דקות עד שעה. לפעמים עד 24–48 שעות.
- ב-Vercel ← **Domains**, ליד הדומיין יופיע **Valid Configuration** (וי ירוק).
- **HTTPS (המנעול) מגיע לבד וחינם.** אין מה לעשות.
- פתחו `https://example.com` בטלפון. האפליקציה צריכה להיפתח.

## ג. Supabase: לאן מותר לחזור אחרי התחברות

כשמתחברים עם Google או לוחצים על קישור במייל, Supabase מחזיר את המשתמש לאפליקציה. מטעמי אבטחה הוא מחזיר רק לכתובות שאישרתם מראש.

1. היכנסו ל-https://supabase.com/dashboard ובחרו את הפרויקט (`cieyeoyuwddobrxjcffw`).
2. בתפריט הצד: **Authentication** ← **URL Configuration** (לפעמים תחת **Authentication** ← **Configuration**).
3. **Site URL**: כתבו את הכתובת הראשית, למשל `https://example.com` (בלי `/` בסוף). לחצו **Save**.
4. **Redirect URLs** ← **Add URL**. הוסיפו אחת-אחת (ושמרו אחרי כל אחת):
   - `https://example.com/**`
   - אם הוספתם גם `www`: `https://www.example.com/**`
   - `https://soccer-team-xxxx.vercel.app/**` (הכתובת שקיבלתם מ-Vercel)
   - `http://localhost:5173/**` (להרצה על המחשב)
   - כתובת המחשב ברשת הביתית, לבדיקה מהטלפון בזמן פיתוח: כרגע `http://10.0.0.189:5173/**`.

> **על הכתובת הביתית:** המספר `10.0.0.189` הוא הכתובת שהראוטר נתן למחשב, והוא יכול להשתנות (למשל אחרי הפעלה מחדש של הראוטר). אם ההתחברות מהטלפון בזמן פיתוח פתאום לא חוזרת לאפליקציה, בדקו מה הכתובת החדשה (היא מופיעה כשמריצים `npm run dev`, בשורה `Network:`) והוסיפו אותה באותה צורה: `http://<הכתובת>:5173/**`.
> אפשר לנסות כתובת אחת שמכסה את כל הרשת הביתית: `http://10.0.0.*:5173/**` (הכוכבית מחליפה את המספר האחרון). כשהטלפון משמש נקודה חמה (hotspot) של iPhone, הכתובת נראית כמו `172.20.10.2`, ואז: `http://172.20.10.*:5173/**`.
> כל זה רק לפיתוח. לאתר האמיתי מספיקות הכתובות עם `https`.

**בודקים:** ברשימה רואים את כל הכתובות, ו-Site URL הוא הדומיין שלכם.

> הקישור במייל עובד **בכל דפדפן** שבו הוא נפתח (גם אם המייל פותח אותו בכרום ולא בספארי). אם המשתמש היה באמצע הצטרפות לקבוצה, הקישור חוזר לכתובת כמו `https://www.example.com/?join=...`. הכוכביות `/**` כבר מכסות את זה.

## ד. מייל: קוד חד-פעמי, הגבלות, ושרת מייל משלכם

### 1. (אחרי שמחברים שרת מייל, סעיף 3) מוסיפים קוד לתבנית המייל
כברירת מחדל המייל של Supabase מכיל רק קישור, והאפליקציה אומרת "שלחנו מייל. פותחים אותו ולוחצים על הקישור". זה עובד גם בלי קוד.
אפשר להוסיף קוד בן 6 ספרות (נוח כשהמייל נפתח במחשב ולא בטלפון). בתוכנית החינמית אי אפשר לערוך את התבניות בלי שרת מייל משלכם, אז קודם סעיף 3, ואז:

1. ב-Supabase: **Authentication** ← **Emails** ← לשונית **Templates** (במסכים ישנים: **Email Templates**).
2. בחרו **Magic Link**.
3. **Subject** (נושא): למשל `הקוד שלך לכניסה לכוחות`
4. **Body** (גוף ההודעה): החליפו את כל מה שיש בזה (אפשר להעתיק כמו שזה):

```html
<div dir="rtl" style="font-family: Arial, sans-serif; text-align: right">
  <h2>כניסה לכוחות</h2>
  <p>הקוד שלך:</p>
  <p style="font-size: 28px; font-weight: bold; letter-spacing: 4px">{{ .Token }}</p>
  <p>מקלידים את הקוד באפליקציה. אפשר גם ללחוץ על הקישור:</p>
  <p><a href="{{ .ConfirmationURL }}">כניסה לכוחות</a></p>
  <p style="color: #888">אם לא ביקשת להתחבר, אפשר להתעלם מהמייל הזה.</p>
</div>
```

5. לחצו **Save**.
6. עשו אותו דבר גם בתבנית **Confirm signup**, עם נושא כמו `אישור ההרשמה לכוחות`. Supabase שולח את התבנית הזאת למי שמתחבר **בפעם הראשונה** (וגם למי שנרשם עם סיסמה), ובלי `{{ .Token }}` המשתמש החדש לא יקבל קוד.

> `{{ .Token }}` ו-`{{ .ConfirmationURL }}` צריכים להיות כתובים בדיוק ככה, עם הסוגריים המסולסלים. Supabase מחליף אותם בקוד ובקישור האמיתיים.
> הקוד הוא 6 ספרות (ברירת המחדל). אם משנים את האורך ב-Supabase, האפליקציה מקבלת גם קודים ארוכים יותר.

7. **מדליקים את שדה הקוד באפליקציה:** בקובץ `.env` בקוד מורידים את ה-`#` מהשורה `# VITE_EMAIL_CODE=1` (או מבקשים ממי שמתחזק את הקוד), והגרסה הבאה עולה עם זה. מעכשיו האפליקציה כותבת "קוד למייל" ומבקשת "הקלידו את הקוד מהמייל". בלי השורה הזאת אין שדה קוד, כי במייל אין קוד.

### 2. ההגבלות של שרת המייל המובנה (חשוב!)
שרת המייל שמגיע עם Supabase בחינם נועד רק לניסיונות:
- הוא שולח **רק מעט מיילים בשעה** (בערך 2–4 בשעה לכל הפרויקט).
- והוא שולח **רק לכתובות של חברי הצוות** בארגון שלכם ב-Supabase. מארגן אחר שינסה להתחבר עם קוד למייל **לא יקבל מייל**.

לכן, לפני שאחרים משתמשים באפליקציה, **מחברים שרת מייל משלכם** (SMTP). אפשרות חינמית ופשוטה: **Resend** (בחינם: עד 3,000 מיילים בחודש ו-100 ביום, נכון לכתיבת המדריך).

### 3. מחברים את Resend (שרת מייל חינמי)
1. היכנסו ל-https://resend.com ונרשמו.
2. **Domains** ← **Add Domain** ← כתבו את הדומיין שלכם (`example.com`). אפשר להשתמש גם בתת-דומיין, למשל `mail.example.com`.
3. Resend יראה כמה רשומות DNS (מסוג **TXT** ו-**MX**). הוסיפו אותן אצל מי שמנהל את ה-DNS (החברה שממנה קניתם, או Vercel אם העברתם אליו), בדיוק כמו בפרק ב'. **אל תמחקו את רשומות ה-A וה-CNAME של Vercel.**
4. חזרו ל-Resend ולחצו **Verify DNS Records**. חכו עד שהסטטוס יהיה **Verified** (דקות עד כמה שעות).
5. ב-Resend: **API Keys** ← **Create API Key** ← שם `supabase`, הרשאה **Sending access** ← **Add**. **העתיקו את המפתח** (מתחיל ב-`re_`). הוא מוצג רק פעם אחת.
6. ב-Supabase: **Authentication** ← **Emails** ← לשונית **SMTP Settings** (במסכים ישנים: **Project Settings** ← **Authentication** ← **SMTP Settings**) ← הפעילו **Enable Custom SMTP**, ומלאו:
   - **Sender email**: `no-reply@example.com` (חייב להיות בדומיין שאימתתם ב-Resend)
   - **Sender name**: `כוחות`
   - **Host**: `smtp.resend.com`
   - **Port**: `465`
   - **Username**: `resend`
   - **Password**: המפתח שהעתקתם (`re_...`)
7. לחצו **Save**.
8. אחרי זה: **Authentication** ← **Rate Limits**. שם רואים כמה מיילים בשעה מותר לשלוח (אפשר להשאיר את ברירת המחדל, או להעלות קצת).

**בודקים:** באפליקציה ← הגדרות ← **התחברות** ← **קישור למייל** ← כתובת של מישהו אחר (לא שלכם) ← **שליחת קישור למייל**. המייל צריך להגיע תוך דקה, מ-`כוחות`. אם לא הגיע, בדקו בספאם.

### 4. (רשות) לבטל את "אישור מייל" בהרשמה עם סיסמה
כשמישהו נרשם עם **מייל וסיסמה**, Supabase שולח לו קודם מייל אישור, ורק אחרי שלחץ עליו אפשר להיכנס.
- כדי לוותר על זה: **Authentication** ← **Sign In / Providers** (במסכים ישנים: **Providers**) ← **Email** ← כבו את **Confirm email** ← **Save**.
- היתרון: נרשמים ונכנסים מיד, בלי לחכות למייל.
- החיסרון: אפשר להירשם גם עם כתובת מייל שאינה שלך. באפליקציה הזאת הסיכון קטן (רק מי שקיבל קישור הזמנה רואה קבוצה), אבל עדיף להשאיר מופעל אם כבר חיברתם שרת מייל.

## ה. התחברות עם Google

### 1. יוצרים פרויקט ב-Google Cloud
1. היכנסו ל-https://console.cloud.google.com עם חשבון ה-Google שלכם (אם מבקשים, אשרו את התנאים).
2. למעלה, ליד הלוגו, יש בורר פרויקטים. לחצו עליו ← **New Project**.
3. **Project name**: `Kochot` ← **Create**. חכו כמה שניות ובחרו את הפרויקט החדש בבורר.

### 2. מסך ההסכמה (OAuth consent screen)
זה המסך שמשתמש רואה כשהוא לוחץ "המשך עם Google".
1. בתפריט (☰): **APIs & Services** ← **OAuth consent screen**. במסכים חדשים זה נקרא **Google Auth Platform**; לחצו **Get started**.
2. **App name**: `כוחות`. **User support email**: המייל שלכם. **Next**.
3. **Audience**: בחרו **External**. **Next**.
4. **Contact information**: המייל שלכם. **Next**.
5. סמנו שאתם מסכימים למדיניות ← **Continue** ← **Create**.
6. **Branding** (או בעמוד של מסך ההסכמה): תחת **Authorized domains** ← **Add domain**, והוסיפו שניים:
   - `example.com` (הדומיין שלכם)
   - `supabase.co`
   
   אפשר גם להוסיף כאן לוגו וקישור לדף הבית (`https://example.com`), אבל זה לא חובה. **Save**.
7. **Data Access** (או **Scopes**): לא חובה. אם רוצים: **Add or remove scopes** ← סמנו `openid`, `.../auth/userinfo.email`, `.../auth/userinfo.profile` ← **Update** ← **Save**. אלה הרשאות בסיסיות (שם ומייל בלבד).

### 3. יוצרים "Client" (מפתח ההתחברות)
1. **Clients** ← **Create client** (במסכים ישנים: **APIs & Services** ← **Credentials** ← **Create Credentials** ← **OAuth client ID**).
2. **Application type**: **Web application**. **Name**: `Kochot web`.
3. **Authorized JavaScript origins** ← **Add URI**. **חובה** (כפתור Google נפתח ישירות מהאתר, ו-Google מסרב לכל כתובת שלא ברשימה). הוסיפו את כולן, בלי `/` בסוף:
   - `https://kadoregel.com`
   - `https://www.kadoregel.com`
   - `https://soccer-team-tau.vercel.app`
   - `http://localhost:5173` (להרצה על המחשב)
4. **Authorized redirect URIs** ← **Add URI**. הוסיפו את כולן, בדיוק כך (בלי `/` בסוף):
   ```
   https://cieyeoyuwddobrxjcffw.supabase.co/auth/v1/callback
   https://www.kadoregel.com/api/gsi
   https://kadoregel.com/api/gsi
   https://soccer-team-tau.vercel.app/api/gsi
   ```
   - הראשונה היא של Supabase: לדרך הגיבוי (אייקון במסך הבית של iPhone, או כש-Google לא נטען).
   - השאר הן של האתר: ב-iPhone/iPad (ובדפדפנים בתוך וואטסאפ/אינסטגרם) Google לא נפתח בחלון קופץ, אלא עובר לדף של Google וחוזר ל-`/api/gsi` באתר. בלי הכתובות האלה Google יראה שגיאה `redirect_uri_mismatch`.
5. **Create**.
6. יופיעו **Client ID** ו-**Client secret**. **העתיקו את שניהם ושמרו במקום בטוח.** ייתכן ש-Google יראה את ה-secret רק עכשיו (אפשר להוריד אותו כקובץ JSON).

### 4. מדביקים ב-Supabase
1. ב-Supabase: **Authentication** ← **Sign In / Providers** (במסכים ישנים: **Providers**) ← **Google**.
2. הפעילו **Enable Sign in with Google** (או **Enabled**).
3. **Client IDs**: הדביקו את ה-Client ID.
4. **Client Secret (for OAuth)**: הדביקו את ה-Client secret.
5. שימו לב לשדה **Callback URL (for OAuth)** שמופיע שם: הוא צריך להיות בדיוק `https://cieyeoyuwddobrxjcffw.supabase.co/auth/v1/callback`, כמו שהדבקתם ב-Google.
6. **Skip nonce check**: להשאיר **כבוי**. (האפליקציה שולחת nonce, וזה מה שמגן מפני שימוש חוזר בטוקן.)
7. **Save**.

> ה-Client ID נמצא גם בקוד, בקובץ `.env` (`VITE_GOOGLE_CLIENT_ID`). הוא ציבורי, לא סוד. אם יוצרים Client חדש ב-Google, צריך לעדכן אותו גם שם וגם ב-Supabase.

## ז. כשמשהו לא עובד

**Google מראה "Error 400: origin_mismatch" / "The given origin is not allowed"**
הכתובת שממנה פתחתם את האפליקציה לא נמצאת ב-**Authorized JavaScript origins** של ה-Client ב-Google Cloud (פרק ה', סעיף 3). הוסיפו אותה בדיוק (עם `https`, בלי `/` בסוף), שמרו וחכו כמה דקות.

**Google מראה "Error 400: redirect_uri_mismatch"**
ב-Google Cloud, ב-Client ← **Authorized redirect URIs** צריכות להיות כל הכתובות מפרק ה', סעיף 3 (של Supabase וגם `.../api/gsi` של כל כתובת של האתר): עם `https`, בלי רווח ובלי `/` בסוף. אם זה קורה רק ב-iPhone, חסרה כתובת `/api/gsi`. שמרו וחכו כמה דקות (לפעמים לוקח עד חצי שעה).

**ב-iPhone: "ההתחברות עם Google לא הצליחה"**
- נסו שוב מאותו דפדפן, בלי לסגור את הלשונית באמצע.
- ב-Supabase ← **Google**: **Skip nonce check** צריך להיות כבוי, ו-**Client IDs** הוא אותו Client ID שב-`.env`.

**אחרי ההתחברות עם Google חוזרים לכתובת אחרת (למשל ל-`vercel.app` במקום לדומיין, או ל-`localhost`)**
הכתובת שממנה התחברתם לא נמצאת ב-**Redirect URLs** ב-Supabase, אז Supabase שולח ל-Site URL. הוסיפו אותה (פרק ג'), עם `/**` בסוף.

**"Access blocked" / "This app is blocked" / "access_denied" מ-Google**
האפליקציה במצב **Testing** והמשתמש לא ברשימת **Test users**. הוסיפו אותו, או לחצו **Publish app** (פרק ה', סעיף 5).

**"Google עוד לא הופעל בפרויקט"**
Google לא הופעל ב-Supabase או לא נשמר (פרק ה', סעיף 4).

**"נשלחו יותר מדי בקשות. נסו שוב בעוד כמה דקות" (Email rate limit exceeded)**
עברתם את מכסת המיילים לשעה. אם עוד לא חיברתם שרת מייל משלכם (פרק ד', סעיף 3), זה יקרה מהר מאוד. אחרי החיבור אפשר להעלות את המכסה ב-**Authentication** ← **Rate Limits**. בינתיים: לחכות שעה, או להתחבר עם Google.

**המייל עם הקוד לא מגיע**
- בדקו בספאם / קידומי מכירות.
- בלי שרת מייל משלכם, Supabase שולח רק לחברי הצוות שלכם ב-Supabase (פרק ד', סעיף 2).
- ב-Resend ← **Emails** רואים כל מייל שנשלח ואם הוא נכשל.

**המייל מגיע בלי קוד, רק עם קישור**
זה המצב הרגיל בלי שרת מייל משלכם: לוחצים על הקישור (בכל דפדפן). אם הדלקתם `VITE_EMAIL_CODE=1`, חסר `{{ .Token }}` בתבנית (פרק ד', סעיף 1). בדקו גם את **Magic Link** וגם את **Confirm signup**.

**"הקישור פג תוקף או שכבר השתמשו בו"**
כל קישור עובד פעם אחת ולזמן מוגבל (בדרך כלל שעה). לפעמים תוכנת המייל "בודקת" את הקישור מראש ומשתמשת בו. שולחים קישור חדש.

**"הקוד שגוי או שפג תוקפו"**
הקוד טוב לזמן מוגבל (בדרך כלל שעה) ורק לפעם אחת. ביקשתם קוד חדש? רק האחרון עובד. לחצו **מייל אחר / שליחה מחדש**.

**"צריך קודם לאשר את המייל"**
נרשמתם עם סיסמה ועוד לא לחצתם על מייל האישור. או שתאשרו, או שתכבו את **Confirm email** (פרק ד', סעיף 4).

**הדומיין לא נפתח / Vercel מראה "Invalid Configuration"**
רשומות ה-DNS עוד לא התעדכנו או שגויות. השוו אחת-אחת למה ש-Vercel מראה. ודאו שאין רשומת **A** ישנה נוספת ל-`@`. לפעמים צריך לחכות כמה שעות.

**רואים גרסה ישנה של האפליקציה אחרי עדכון**
האפליקציה בודקת עדכונים בכל פתיחה, כשיש אינטרנט.
- אם היא פתוחה ברקע (לא נסגרה), היא לא נטענת מחדש: סגרו אותה לגמרי (החלקה למעלה ברשימת האפליקציות הפתוחות) ופתחו שוב.
- בדפדפן: רעננו את הדף. לפעמים צריך לסגור ולפתוח פעמיים.
- הנתונים שלכם (שחקנים, קבוצות) **לא נמחקים** מזה. הם שמורים בנפרד.

**ב-Vercel ה-Deploy נכשל (אדום)**
לחצו על ה-Deployment ← **Building** / **Logs**, וקראו את השורות האדומות האחרונות. בדרך כלל זו שגיאה בקוד שנכנס לענף, והגרסה הקודמת ממשיכה לעבוד באתר בינתיים. העבירו את השגיאה למי שמתחזק את הקוד.
